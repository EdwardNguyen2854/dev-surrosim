# v2.0 GNN field prediction (normalised targets, held-out evaluation)

> Candidate metrics. The model was selected on validation data only; test and
> challenge values below were computed afterwards and never used for selection.


- Graph dataset: `data/graphs_v2` (index sha `6ec9bcac8ffb...`), splits {'train': 1722, 'test': 369, 'val': 369, 'challenge': 349}
- Device: `cuda`, config {'seed': 42, 'epochs': 60, 'patience': 12, 'hidden': 80, 'layers': 8, 'learning_rate': 0.001, 'grad_accumulation': 4, 'target_scaling': 'nominal_v1'}
- Node features: 31; targets: 9 components (displacement + stress tensor)
- Best model by validation global-VM MAPE: **meshgraphnet**

Scalar values are obtained by reducing the predicted field exactly like
the FEA labels are reduced (global max, and the shape's stress-riser
ROI definition). Field errors are node-wise errors relative to the
per-case peak value.

## Notes and limitations

- The GNN is trained on the coarse `graph` mesh profile; labels are FEA
  solutions of those same meshes (consistent field supervision).
- Field accuracy is measured against the FEA peak per case; local values
  near zero stress have large relative error but small absolute error.
- The challenge split (corner-of-design-space) is never used for fitting
  or model selection.
- Candidate metrics require per-shape review before production use.
