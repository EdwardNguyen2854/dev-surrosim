# Engineering application and inference API

The application exposes the scalar ensemble, the MeshGraphNet field model and
the validated CalculiX solver through one FastAPI service and a React web app.
It was introduced in v0.5 as a Streamlit prototype and rebuilt in v1.1 as a
React/TypeScript single-page app with a background-job API.

## Running

```bash
# API + app: serves apps/web/dist when a production build exists
python -m surrosim serve                     # http://127.0.0.1:8003

# Development: Vite dev server on :5173, proxying the API on :8003
cd apps/web
npm install
npm run dev
```

## HTTP API

| endpoint | purpose |
| --- | --- |
| `GET /api/health` | liveness, registry path, CalculiX and field-model availability |
| `GET /api/config` | design defaults/bounds, optimizer bounds, mesh policy, capabilities |
| `GET /api/model` | registry path, dataset hash, selected models, git commit |
| `GET /api/domain` | supported design-space bounds and material defaults |
| `POST /api/predict` | surrogate prediction for one design |
| `GET /api/reports/model` | per-target model comparison, figures, model/dataset cards |
| `POST /api/jobs/fea-verify` | run the real CalculiX case for a design |
| `POST /api/jobs/field-predict` | MeshGraphNet nodal-field prediction |
| `POST /api/jobs/optimize` | constrained mass minimization on the surrogate |
| `GET /api/jobs/{id}` | job status, stage, progress, log stream and result |
| `GET /api/fields/{id}?field=...` | surface-mesh payload for the 3D viewer |

`POST /api/predict` request (also documented by FastAPI's OpenAPI UI at
`/docs`):

```json
{
  "length_mm": 120, "width_mm": 40, "thickness_mm": 6,
  "hole_diameter_mm": 12, "hole_x_mm": 60, "force_n": 500
}
```

Response essentials:

- `predictions`: each target with value (and ensemble spread where available);
  the ROI target is `null` for no-hole designs;
- `confidence`: bounds check with violation messages, `ood_ratio`,
  `ood_level` (`in_domain` / `caution` / `out_of_domain`), member spread,
  `recommendation` (`trust` / `caution` / `run_fea`) and human-readable
  reasons;
- `model`: registry path, dataset sha256, git commit of the training run;
- `latency_ms` and the median FEA solve time for context.

## Background jobs

Solver-level operations are queued as jobs so HTTP requests never block:

- a small thread pool runs the job workers; the two meshing pipelines (FEA
  verification and field prediction) execute in spawned worker processes,
  because Gmsh installs a SIGINT handler that is only legal on the main
  thread of the main interpreter;
- each job streams a bounded log and stage/progress updates, polled through
  `GET /api/jobs/{id}`;
- artifacts are written under `outputs/jobs/<id>/`; field payloads are served
  separately so the job JSON stays small;
- failures keep their traceback in the job log and the UI reports them
  without losing earlier progress.

## Confidence and domain logic

1. **Hard bounds** — the sampled design space (`DesignSpace`): dimensions,
   force, hole diameter relative to width, hole position relative to length.
   Violations force `run_fea`.
2. **Distance OOD** — standardized-feature distance to the 5th nearest
   training design, normalised by the 95th percentile of the same statistic
   within the training set (`ood_ratio`). Thresholds: >1.5 caution,
   >2.5 out of domain.
3. **Ensemble disagreement** — spread between the GP and MLP members in log
   space; >15% forces caution.
4. For no-hole designs the hole position is set to mid-span before feature
   construction, matching how those cases were sampled.

## Web application

- **Design Explorer** — shape-family selector, per-shape parameter controls
  and a live parametric schematic (plate/taper/two-hole in elevation,
  stepped and L-bracket in side view, I-beam cross-section) with dimensions
  and boundary conditions, instant predictions with the confidence/OOD panel
  and the shape-specific analytical beam reference.
- **Field Prediction** — MeshGraphNet nodal fields on the coarse graph mesh
  with a Plotly 3D viewer and scalar readouts.
- **FEA Verify** — runs the real CalculiX case for the current design
  (production mesh policy), streams the job log, tabulates surrogate vs FEA
  error and renders Von Mises / displacement fields.
- **Optimization** — differential evolution on the surrogate with candidate
  verification against the solver, evaluation scatter and convergence charts.
- **Model & Dataset** — registry metadata, per-target model comparisons,
  parity figures and the model/dataset cards.
- Capability gating: pages disable their run buttons and explain the setup
  step when CalculiX or the GNN checkpoint is missing.

Design tokens live in `apps/web/tailwind.config.ts` (paper/graphite palette,
IBM Plex Sans + Mono); the schematics are parametric SVG components that scale
to any design, one per shape family.

## Desktop shell (Windows)

`apps/desktop` is an Electron wrapper for local use. It resolves the repository
and `.venv`, picks the loadable v2 registry (or candidate/v1 fallback), starts
`python -m surrosim serve` on a free port as a child process, waits for
`/api/health`, and opens the built SPA in a native window. Closing the window
kills the backend process tree; logs land in `outputs/desktop/backend.log` and
the window position is remembered in `outputs/desktop/window-state.json`.

```bat
start-desktop.bat        # from the repository root
```

`SURROSIM_DESKTOP_DEV=1` loads the Vite dev server instead of the built app
(with `start-dev.bat` or an automatically started API on :8003). The shell
needs no API changes: `serve --registry/--field-model` and the SPA mount
already cover it. A portable Electron build (`npm run dist`) exists but still
expects the repository; sharing with machines that have no Python environment
would require a frozen sidecar and is out of scope for the personal launcher.

## Docker

```bash
docker compose -f docker/docker-compose.yml up --build
```

The image builds the frontend in a Node stage, installs CPU-only torch and
serves app + API together on `http://localhost:8000`. CalculiX is not bundled,
so FEA verification degrades gracefully inside containers.

## Testing

`tests/test_serving.py` covers prediction, ROI suppression, bounds
enforcement, OOD growth, the FastAPI contract, reports, job lifecycle
(including a real spawned worker process) and the field payload used by the
3D viewer. The frontend is type-checked and built in CI (`npm run build`).

## Limitations

- Confidence signals are heuristic, not calibrated probabilities.
- OOD is measured in the 12-dimensional feature space, not in geometry space;
  unusual shapes inside the parameter box can still be mis-scored.
- Jobs are in-memory: restarting the API cancels running jobs (artifacts
  already written under `outputs/jobs/` remain on disk).
- The app is a local engineering demo; it has no authentication and must not
  be exposed publicly as-is.
