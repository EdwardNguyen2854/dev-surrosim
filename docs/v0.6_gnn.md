# SurroSim v0.6 — MeshGraphNet field prediction

v0.6 adds geometry-aware field prediction: a coarse-mesh FEA dataset, a
mesh-graph export pipeline and a MeshGraphNet-style message-passing model
that predicts nodal displacement and the full stress tensor. Scalar
engineering quantities are obtained by reducing the predicted field with the
same definitions used for the FEA labels.

## Pipeline

```
design table ──► coarse FEA (graph mesh profile) ──► mesh graphs
                                                        │
                     MeshGraphNet training ◄────────────┘
                              │
              field prediction + scalar reductions (app)
```

```bash
surrosim dataset run --designs data/designs_v1.csv --out data/runs_graph \
    --jobs 6 --mesh-profile graph --ccx ccx
surrosim graph export --designs data/designs_v1.csv --runs data/runs_graph --out data/graphs_v1
surrosim train gnn --graphs data/graphs_v1 --runs data/runs_graph --out models/gnn/v1
```

## Graph dataset (`data/graphs_v1`)

- 644 graphs (same designs and splits as dataset v1), mean 2,013 nodes and
  ~10,400 edges per graph; corner nodes of the C3D10 mesh with corner-tet
  connectivity.
- Node features (15): scaled coordinates, hole-radial ratio, fixed/load/hole
  surface flags, and an 8-component broadcast global design vector.
- Edge features (4): relative position vector and length, scaled by thickness.
- Targets (9): ux, uy, uz and SXX, SYY, SZZ, SXY, SYZ, SZX from CalculiX.
- Gating: cases must pass the same solver gates, have `mesh_min_sicn > 0`
  and at least 200 corner nodes; skipped cases are listed in the manifest.

The coarse **graph mesh profile** is C3D10 with global size
`clamp(t/1.5, 2.5, 4.0) mm` and hole grading to `min(0.6 × global, d/6)`.
Coarse meshes keep message passing affordable on consumer GPUs; scalar
labels for the accurate surrogate pipeline still come from the production
profile. High-order optimisation (`Mesh.HighOrderOptimize = 2`) is enabled
to guarantee positive Jacobians on coarse quadratic meshes.

## Model and results

MeshGraphNet-style encoder–processor–decoder: node and edge encoders
(SiLU MLPs), 8 message-passing blocks with residual LayerNorm, decoder to
9 outputs; trained on normalised targets with AdamW + cosine schedule,
gradient accumulation 4, early stopping. 150 epochs took ~24 minutes on an
RTX 3050 (4 GB). Message passing is implemented in pure PyTorch
(`index_add` scatter), so the field stack has no PyG or compiled-extension
dependency — it runs anywhere torch does, including the CPU-only container.

Reduced from predicted fields, versus FEA (same coarse meshes):

| model | split | max disp MAPE % | global max VM MAPE % | ROI max VM MAPE % | field VM median err % | field VM p95 err % |
| --- | --- | --- | --- | --- | --- | --- |
| MeshGraphNet | test | 8.68 | 2.63 | 3.22 | 0.80 | 20.91 |
| MeshGraphNet | challenge | 29.31 | 9.14 | 8.58 | 1.47 | 50.20 |
| node MLP baseline | test | 14.92 | 10.47 | 12.00 | 1.73 | 51.16 |
| node MLP baseline | challenge | 56.60 | 28.24 | 33.79 | 3.44 | 102.13 |

- Message passing clearly beats the coordinate MLP baseline (~4× lower
  challenge error), demonstrating a genuine benefit from geometry-aware
  learning.
- Global peak-stress error on the random test split (2.63%) is close to the
  scalar ensemble (2.30%) while additionally providing full fields.
- Field errors are measured relative to each case's peak value; median
  node-wise error is below 1% on test designs.

## Application integration

The engineering app includes a **Field Prediction** page: it meshes the current
design with the graph profile, runs the GNN (~1.2 s end-to-end on a laptop),
shows the reduced scalar quantities and renders 3D Von Mises / displacement
fields. This is the first v1.0 capability that visualises spatial results
rather than scalar numbers.

## Limitations

- Fields are predicted on the coarse graph mesh; refinement to production
  meshes would require either retraining at higher resolution or a
  mesh-agnostic formulation.
- Max-displacement error (8.7% test) is dominated by the max-over-nodes
  reduction of a field whose median error is <1%; the scalar ensemble
  remains the better estimator for extreme scalar values.
- Linear elasticity, single load case, no contact/plasticity/dynamics.
- Challenge-split errors (9–50%) show the expected degradation at the
  corners of the design space; the app's domain checks still apply.
